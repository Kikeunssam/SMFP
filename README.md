# 일월오봉 — 리듬 놀이터

소리를 쌓으면 해와 달, 다섯 봉우리, 소나무와 물결이 함께 움직이는 한국어 픽셀 리듬 도구입니다. 화면·버튼·게이지·글꼴을 게임처럼 통일했습니다.

## 실행

Node.js 20.19+ 또는 22.12+가 필요합니다. Node 24에서 확인했습니다.

```sh
npm install
npm run dev
```

표시된 로컬 주소에서 **재생**을 누르면 시작합니다. 브라우저 정책에 따라 첫 클릭 이후 소리가 나옵니다.

```sh
npm test          # 핵심 동작 검사
npm run build    # 타입 검사 + 배포용 빌드
npm run preview  # 배포용 빌드 미리보기
```

## 놀이 방법

- **6박·8박·12박**을 선택합니다. 한 칸이 한 박이며, 빠르기는 분당 박 수입니다. 120이면 한 칸이 0.5초입니다. 12박은 화면에서 3칸씩 묶어 표시합니다.
- 칸을 눌러 소리를 켜거나 끕니다. Shift + 클릭은 세기를 바꿉니다.
- 악기 이름 또는 숫자 1–7로 소리를 미리 들어 봅니다. 그림의 달·해·가운데 산·소나무도 누를 수 있습니다.
- **쉼**은 해당 악기를 쉬게 하고, **독주**는 선택한 악기만 들려줍니다. 여러 독주를 함께 선택할 수 있습니다. 쉼이 독주보다 우선합니다.
- **재생 / 스페이스바**로 연주를 시작하거나 멈춥니다. 정지하면 첫 박으로 돌아갑니다.
- **둥둥 행진 / 달빛 산책 / 신나는 물결**은 시작 리듬입니다. 선택하면 현재 리듬을 교체합니다.
- **비우기 / 되돌리기**, 악기별 음량, **울림 / 메아리 / 밝기**를 제공합니다.
- 화면 아래 **움직임: 살살 / 신나게**로 모션 강도를 바꿉니다. 운영체제의 동작 줄이기 설정도 반영합니다.
- 리듬과 음량·효과는 브라우저에 저장됩니다. 다른 탭으로 이동하면 연주가 멈춥니다.
- 태블릿에서 긴 리듬 표는 좌우로 스크롤됩니다. 조작하기 쉽도록 버튼 크기를 유지합니다.

## 저장 데이터

현재 저장 키는 `smfp-pattern-v3`입니다. 이전 v1/v2 저장도 읽습니다. 기존 16/32칸 데이터는 앞 12칸과 7개 악기의 음량·쉼·독주 설정을 유지해 변환하고, 물결 트랙은 제거합니다. 이전 저장 키는 삭제하지 않습니다. 6박·8박 모드에서도 숨겨진 뒷부분의 칸은 유지되므로 길이를 늘리면 다시 보입니다.

## 그림과 글꼴

첨부한 콘셉트와 모션 스토리보드는 `assets/reference/`에 보관했습니다. 이미지를 배경 한 장으로 붙이지 않고 Phaser에서 각 요소를 별도 픽셀 그래픽으로 그립니다. 달은 왼쪽, 해는 오른쪽에 배치하고 표정·눈 깜박임·겹겹의 산·소나무·폭포·소용돌이 파도·구름을 반영했습니다. 각 요소는 악기 이벤트에 반응합니다.

Galmuri 한글 픽셀 글꼴을 앱에 포함합니다. 외부 글꼴 서버 접속이 필요 없습니다. 작성자는 Lee Minseo이며 SIL Open Font License 1.1을 따릅니다. 패키지의 라이선스를 참고하세요. 사용하는 기본/굵은 WOFF2 두 파일만 빌드에 포함합니다.

## 실제 국악기 음원

사용자가 제공한 국립국악원 국악 디지털 음원 7개를 AAC 128kbps M4A로 변환해 `public/samples/`에 연결했습니다. 원본 WAV 파일은 수정하지 않았습니다. 총 22,142,186바이트에서 1,498,412바이트로 약 93.2% 줄었습니다.

- 용고, 장구, 징, 자바라, 나발, 나각, 태평소의 실제 녹음 사용.
- 82.57초짜리 태평소 음계 녹음은 전체 M4A를 보관하되 리듬 칸에서는 첫 발음 구간을 1초 동안 재생합니다. 나발·나각도 리듬용 게이트를 적용합니다.
- 앞부분 무음은 재생 시작 위치로 건너뛰며, 음높이/재생 속도는 바꾸지 않습니다.
- 파일별 start/gate/maxVoices는 `src/config/sampleManifest.ts`에 있습니다. 징의 긴 잔향은 유지하고 관악기 중복 발음은 1개로 제한합니다.
- 실패 시 합성음을 대신 내지 않고 무음으로 처리하며 로드 실패 개수를 표시합니다.
- 변환 기록은 `public/samples/conversion-report.json`에 있습니다. macOS에서 다시 변환하려면 `python3 scripts/convert_samples.py /원본/WAV/폴더`를 실행합니다.

악기 샘플은 국립국악원 '국악 디지털 음원' 자료를, 출정 음성은 사용자가 제공한 녹음을 활용하였습니다.

## 소리와 움직임

자바라는 0.65초 감쇠하는 큰 픽셀 햇살, 용고는 다섯 봉우리를 묶은 레이어의 최대 7px 들썩임, 나각은 양쪽 소나무의 최대 9px 들썩임과 작은 좌우 움직임에 연결됩니다. 장구는 폭포에 연결됩니다. 파도는 칸 입력·타격·밀도에 반응하지 않으며 일정한 기본 흐름만 유지합니다. 움직임 줄이기 설정은 계속 적용됩니다.

## 코드 구조

- `src/audio/`: Web Audio 시계 기반 예약 재생, 샘플 관리, 음량 및 효과. 25ms마다 확인해 100ms 앞까지 예약하며, 한 박의 길이는 `60 / BPM`입니다.
- `src/sequencer/`: 6·8·12박 패턴, 저장 형식 검증·변환, 쉼·독주 판정.
- `src/visual/`: 오디오와 독립된 이벤트 버스, 누적되지 않는 모션, 밀도에 따른 에너지.
- `src/game/`: 한국어 시작 안내와 각 요소가 분리된 640×360 픽셀 풍경.
- `src/config/`: 악기, 샘플, 모션, 교체 가능한 그림 설정.
- `src/main.ts`, `src/style.css`, `src/fonts.css`: 한국어 조작 화면과 픽셀 테마.

## 검증과 남은 작업

10개 테스트로 패턴 검증·이전 저장 변환·박 길이·6/8/12박 반복·오디오 초기화 중 정지·쉼/독주·모션·7개 M4A 파일 로드와 무음 실패 처리를 확인합니다. 데스크톱과 태블릿 브라우저에서 조작과 배치를 확인했습니다. 검증 화면은 `docs/pixel-ko-desktop.jpg`, `docs/pixel-ko-tablet.jpg`입니다.

다음 단계는 실제 태블릿에서 소리와 화면 지연 측정, 세부 픽셀 아트와 터치 조작 다듬기입니다. 초기 구현 기록 및 원본 지시 문서는 `docs/`에 보관합니다. Opus 리뷰는 아직 진행하지 않았습니다.

## 궁궐별 풍경 선택

제목 옆에서 **경복궁 근정전 / 창덕궁 인정전 / 덕수궁 중화전**을 선택합니다. 작은 화면에서는 제목 아래에 표시합니다.

- 경복궁: 푸른 하늘, 황토색 둥근 산, 굽은 붉은 소나무, 가는 선이 겹친 물결.
- 창덕궁: 청록색 각진 능선, 넓게 뻗는 소나무 가지, 높은 파도와 물보라.
- 덕수궁: 밝은 비단빛 하늘, 완만한 연두 능선, 가느다란 나무, 잔잔한 물결.

첨부 사진을 참고한 픽셀 재해석입니다. 연주를 멈추지 않고 풍경을 바꿀 수 있으며 리듬·음량·빠르기는 유지됩니다. 선택한 궁궐은 별도 저장 키 `smfp-palace-v1`에 저장됩니다. 테마의 색상·산 윤곽·소나무와 물결 설정은 `src/config/palaceThemes.ts`에서 조절합니다. 그리기 객체는 재사용해 반복 전환 시 새 객체가 누적되지 않도록 했습니다.

### 태평소 가락 놀이
태평소는 새 대취타 연주 녹음에서 고른 가락 3종과 쉼을 세 자리에 배치합니다. 원래 연주 속도와 음높이를 유지하며 필요한 만큼 6·8·12박 바퀴를 사용하고, 다음 첫 박에 다음 조각으로 넘어갑니다. 내부 선율을 박마다 맞추는 타임 스트레칭은 아직 적용하지 않았습니다. 화면의 빛 궤적과 구름은 가락의 진행과 실제 녹음의 세기에 반응합니다. 구간 경계는 청취 후 다듬을 수 있도록 설정 파일로 분리했습니다. 현재 자동 테스트 13개를 통과했습니다.

### 대취타 출정 연출
첫 재생 전에는 픽셀 풍경을 고정하고 해와 달의 눈을 감깁니다. 첫 재생에서 제공된 8.23초 M4A 음성에 낮은 음정, 약한 흔들림, 짧은 메아리를 적용하고 화면 중앙에 ‘명금일하 대취타 하랍신다.’ 가로 족자를 펼쳐요. 음성이 끝나면 족자를 접고 첫 장단부터 연주합니다. 일시정지 후 이어 재생할 때 출정 연출은 반복하지 않아요.

## GitHub + Firebase Hosting 배포

Firebase Hosting은 `firebase.json`에서 `dist/`를 배포하도록 설정했습니다. 배포할 때는 Firebase 프로젝트 ID를 `.firebaserc`에 연결한 뒤 Firebase CLI로 로그인하고 `npm run deploy:firebase`를 실행합니다. 소스 저장소는 GitHub에 별도로 올립니다. 이 작업공간에는 아직 GitHub 원격 저장소와 Firebase 프로젝트 연결이 없으므로 실제 업로드와 배포에는 GitHub 저장소 URL 및 Firebase Project ID가 필요합니다.
